1. Інфраструктура та безпека AWS
Security Groups (SG) та Network Access Control Lists (NACL)
Це два рівні мережевого захисту в AWS:

Security Groups: Це "фаєрвол" на рівні екземпляра (Instance). Вони працюють за принципом Stateful: якщо ви дозволили вхідний трафік, вихідний дозволяється автоматично. Ви можете лише дозволяти (Allow) трафік.

NACL: Це "фаєрвол" на рівні підмережі (Subnet). Працюють за принципом Stateless: якщо ви дозволили вхід, ви повинні окремо прописати правило для виходу. Можна і дозволяти, і явно забороняти (Deny) трафік.

Region, Availability Zone (AZ) та Subnet
Region: Географічна локація (наприклад, us-east-1 у Вірджинії). Це фізично ізольована група дата-центрів.

Availability Zone (AZ): Один або кілька дискретних дата-центрів всередині Регіону. Вони з'єднані каналами з низькою затримкою. Потрібні для відмовостійкості.

Subnet: Діапазон IP-адрес у конкретній AZ. Ви розгортаєте ресурси (наприклад, EC2) саме в підмережах.

Чому потрібно більше одного аккаунту AWS?
Використання кількох аккаунтів (через AWS Organizations) допомагає:

Ізоляція оточень: Розділення Dev, Test та Prod (помилка в Dev не покладе Prod).

Безпека: Обмеження радіуса ураження (Blast Radius) у разі зламу одного аккаунту.

Фінанси: Простіше відстежувати витрати різних департаментів або проєктів.

Безпека Root аккаунту
Root — це користувач з абсолютним доступом. Правила безпеки:

Ніколи не використовувати його для повсякденних завдань.

Обов'язково увімкнути MFA (Multi-Factor Authentication).

Видалити всі Access Keys (ключі доступу для програм).

Створити окремого IAM-користувача з правами адміністратора для роботи.

IAM та IAM Groups
IAM (Identity and Access Management): Сервіс для керування доступом до ресурсів AWS. Ви визначаєте, хто може увійти та що він може робити.

IAM Groups: Це логічні групи користувачів (наприклад, "Developers", "Admins"). Ви призначаєте права групі, а не кожному користувачу окремо, що спрощує адміністрування.

2. Концепції хмарних обчислень
Типи хмарних обчислень (Service Models)
IaaS (Infrastructure as a Service): Ви отримуєте "залізо" (віртуальні машини, мережі). Ви самі ставите ОС та софт. (Приклад: AWS EC2).

PaaS (Platform as a Service): Вам дають платформу (середовище розробки). Ви дбаєте лише про код. (Приклад: AWS Elastic Beanstalk).

SaaS (Software as a Service): Готовий додаток через браузер. Ви тільки користуєтесь. (Приклад: Gmail, Google Drive).

Моделі розгортання
Public Cloud (Публічна): Ресурси належать провайдеру (AWS, Azure) і використовуються багатьма клієнтами. Коли: Для стартапів, сайтів, більшості бізнес-задач.

Private Cloud (Приватна): Хмара тільки для однієї компанії (у власному дата-центрі). Коли: Для банків або урядових структур з надвисокими вимогами до безпеки.

Hybrid Cloud (Гібридна): Поєднання приватної та публічної хмар. Коли: Коли частину даних треба тримати "вдома", а пікові навантаження виносити в публічну хмару.

Хмара vs Звичайний веб-хостинг
Хостинг: Зазвичай має фіксовані ресурси. Важко масштабувати. Ви платите за пакет, навіть якщо не використовуєте його.

Хмара: Еластичність (масштабування за лічені секунди) та модель Pay-as-you-go (плата тільки за спожиті ресурси щосекунди/щохвилини).

Безпека у хмарі (Shared Responsibility Model)
Безпека в хмарі базується на моделі спільної відповідальності:

Провайдер (AWS) відповідає за безпеку самої хмари (захист фізичних серверів, охорона дата-центрів, справність гіпервізорів).

Клієнт (Ви) відповідаєте за безпеку всередині хмари (налаштування фаєрволів, оновлення ОС на EC2, шифрування даних, керування доступами користувачів).
